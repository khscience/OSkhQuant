# 从 V2.1 升级到开源版 2.2

2.2 是独立安装的新程序，**不会覆盖、卸载或改动 V2.1**。两个版本可以同时存在，确认 2.2 没问题后再自行卸载 V2.1。

## 1. 安装与首次启动

1. 安装 `khQuantOS_Setup_V2.2.x.exe`。安装程序检测到 V2.1 时只会提示，不会卸载它。
2. 首次启动引导里：
   - 选一个数据目录（默认 `%LOCALAPPDATA%\KhQuantOS\khData`，建议换到非系统盘）；
   - 勾选「导入 V2.1 的设置」：会只读地复制无风险收益率、日志设置、上次打开的配置文件和策略路径；
   - 勾选「下载沪深300」：作为回测基准。
3. 启动后会询问是否把 V2.1 的策略（`%LOCALAPPDATA%\KhQuant\strategies`）复制到
   `文档\KhQuant_OS\strategies`。只复制，V2.1 目录里的文件不动。

## 2. 数据：从 miniQMT 换成本地 DuckDB

V2.1 从 miniQMT 取数，2.2 只读本地 DuckDB，需要先把数据下载到数据目录：

- 日线、5 分钟线：「数据管理 → BaoStock导入」，免费，不用注册账号；
- 1 分钟线：「数据管理 → Tushare导入」，需要在设置里填 Tushare Token，并开通 `stk_mins` 权限；
- Tick：两个数据源都没有，需要自行导入。

**预热期**：V2.1 的 `khHistory` 缺数据时会自动下载，2.2 不会，缺数据时返回空（默认会弹窗提示）。
下载时开始日期要早于回测开始日期：比如策略用 60 日均线，至少往前多下 3 个月。
否则策略可能「不报错也不交易」。

## 3. 旧配置文件（.kh）

可以直接加载。下面这些字段会被忽略，不影响回测：

| 字段 | 说明 |
| :--- | :--- |
| `system.userdata_path` | miniQMT 路径，开源版不用 |
| `data_mode` | 实盘数据获取方式，开源版只做回测 |
| `run_mode` | 一律按回测处理 |
| `web_run_id`、`match_engine` 等 | 网页端和旧撮合设置 |

回测区间要在已下载的数据范围内。

## 4. 策略代码

- `from khQuantImport import *` 的用法不变，`khHistory`、`khKline`、`khMA`、`khPrice`、`khGet`、`generate_signal`、
  MyTT、缠论工具等函数名和参数都与 V2.1 相同。
- `xtdata.*`（`get_market_data_ex`、`subscribe_quote`、`get_full_tick` 等）在开源版里不可用，调用时会提示改用
  `khHistory` / `khKline` / `khPrice`。
- `xtconstant.STOCK_BUY` 等常量仍可使用，取值和 xtquant 相同。

## 5. 常见问题

- **回测不交易**：多半是数据没下够，看日志里 khHistory 缺数据的提示，把下载开始日期往前挪。
- **没有基准线、没有 α / β**：结果窗口顶部会提示缺少基准，点「补基准数据」下载 000300.SH 后重新回测。
- **同一策略在 2.2 和 V2.1 上结果不同**：数据源不同（BaoStock / Tushare 与 miniQMT 的复权和成交量口径不完全相同），
  内核本身与 CS 版一致。
- **同时装了 CS 版**：不要让两边共用数据目录，用「数据管理 → 复制CS数据」复制一份。
